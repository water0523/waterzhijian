# 启动性能优化

目标：减少打开编辑器时的主线程停顿，保持离线、公式渲染、主题即时预览和草稿恢复完整。

1. 记录 Chrome / Edge 的首次打开、已保存文章重开、主题侧栏保持打开三种场景。测量首屏内容、文章就绪、长任务、主题预览生成量，保留原版作为同机对照。
2. 主题库关闭时不生成缩略图；打开后先建立可搜索的主题列表，只生成可见与即将进入视口的实际排版预览。沿用预览缓存，保留悬停、收藏排序、键盘与完整预览。
3. 检查没有待恢复草稿时是否仍存在可省去的等待。只跳过没有候选记录的恢复探测，存在草稿时保留完整并发检查与恢复规则。
4. 复测启动时长和最长阻塞，检查主题滚动 / 搜索 / 悬停及保存 / 多窗口恢复。更新离线文件、Pages 构建和源码包，记录测量范围。

完成：主题侧栏改为按需建立并用 IntersectionObserver 生成可见范围的真实缩略图；无恢复候选时省去活跃窗口探测。Chrome 三次中位数首次 916→504ms、重开 329→138ms；Edge 首次 894→550ms、重开 376→146ms。两款浏览器的侧栏、收藏与存储恢复回归通过。离线 / Pages 构建和说明同步更新。

第二轮：用户要求继续减少启动负担，优先恢复最后文章及主题。

- 将数学、Word 和代码高亮引擎编译成单文件内的静态惰性模块，首次实际使用时同步启动，避免无公式正文初始化数学引擎；保留离线能力、公式编号和缓存。
- 七幅示例图作为静态数据保存在 HTML 中，示例或完整主题预览请求时才解析成图片数据，启动脚本由约 5.5 MB 减至约 1.2 MB。
- 取消启动时第二次重建同一编辑器状态，直接使用已恢复的文章和设置。
- 验证素笺、格物文史、新闻周刊的原主题 / 原文恢复及未用模块不启动，再验证首次公式、代码、Word、示例图及实际导出。
- 完成：备用模块 gzip 压缩静态内嵌，主脚本 1.22 MB，单文件 4.71 MB；两款浏览器各 7 组模块检查通过，保存的纯文字稿重开中位数约 90–103ms。公式 / 原图 / Word / PDF / 核心回归保持。
