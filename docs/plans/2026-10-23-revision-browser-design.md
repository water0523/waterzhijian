# 第九轮：可检索、可命名的版本管理

第八轮工具栏可读性已完成双浏览器检查并推送 d291c9a。继续用户恢复后的持续优化授权。

现状：历史页完整逐条铺开，无名称搜索、只看手动、重命名或已选摘要。revisionKey 对整个恢复点 JSON 取指纹，直接修改 label 会改变身份；只在本机替换它，旧窗口保存时仍可能带回旧记录。

方案选择：重建所有版本的身份会扩大旧备份兼容风险；直接修改标签再标记删除会在并发改名时产生两个副本。因此保留原恢复点内容与指纹，在文章上新增可选 revisionNames 元数据，以版本指纹索引显示名称。合并使用时间戳和事件 ID 的确定顺序，删除仍以原版本指纹为准。元数据只属于手动版本，未知/损坏条目忽略。普通正文、文章名称、排版、撤销和自动版本保留策略不变。

备份导入会规范化版本和重映射图片，因此同时建立原指纹到导入后指纹的映射，再导入显示名称。旧备份没有此字段仍可使用；新字段不改变版本 1 的文章正文结构。

界面保留现有 DOM ID 与比较/恢复入口。增加名称/主题/日期搜索、只看手动、结果计数、估算历史数据体积；先显示 50 项，按需继续显示。全选作用于当前筛选结果，保留跨筛选选择但明确标注筛选外数量，支持清空选择。删除确认显示手动/自动数量与名称摘要。手动保存支持可选名称；逐行改名使用表单，Enter 保存、Esc 取消，并保护中文输入法组合输入。搜索、选择及输入草稿在比较后返回时保留。异步保存结束只更新仍属于本次操作的窗口，不能把后开的弹窗覆盖。

验收：100+ 手动版本搜索/空结果/筛选/分批显示、跨筛选选择与删除摘要、手动/自动区分、重命名/取消/空名/长度/特殊字符/重复应用、名称变更不修改恢复点内容与正文。两窗口改名/保存/删除/并发冲突、保存失败与迟到完成；改名后比较/恢复、刷新、含重复图片的 ZIP 往返及旧包兼容。三套界面日夜检查，并继续完整回归、发布包一致性验证后推送。

用户已要求这批完成后暂停。只完成本批验证、打包和推送，然后暂停持续目标，不开启下一轮。相同正文的历史元数据可合并；若另一窗口也改了正文，继续采用既有冲突副本保护，不把这种情况冒称为纯名称合并。

保存失败在版本窗口内保持可见提示，提供“重试保存”，避免原生弹窗使背景顶栏错误难以发现。重试成功才隐藏错误，未保存的名称仍在当前窗口保留。
