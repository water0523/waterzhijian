# 把一篇 Markdown 整理成可交付文章

写完并不等于可以发送。一篇可交付的文章，除了内容，还需要清楚的标题、能读的代码、可靠的引用，以及别人拿到后能打开的文件。这篇教程就从这些小处开始。

## 先搭结构，再调颜色

正文开头使用一个一级标题。大节用二级标题，节内的小问题用三级标题，不要为了视觉上的字号去跳过结构层级。

```markdown
# 文章标题

这是一段导语。

## 问题是什么

先把问题讲清楚，再给出例子。

### 哪些条件需要保留

把限制与注意事项写在这里。
```

当主题本身会给章节编号时，可以使用工具栏中的“清除标题序号”，避免原文的一、二、三与主题编号重复。这个操作只针对标题开头的序号，不应改变代码里的内容。

## 让代码成为解释的一部分

较短的标记可以直接使用 `article.title`，多行内容则放进代码块。代码块不应把复制按钮、行号或界面提示混进真正的源码。

```javascript
const article = {
  title: "把问题讲清楚",
  tags: ["写作", "阅读", "可维护的结构"],
};

const result = JSON.stringify(article, null, 2);
console.log(result);
```

如果需要展示一条较长命令，也应当能看清它的开头与结尾，而不是只能猜测被裁掉的部分：

```text
publish --title="把一篇Markdown整理成可交付文章" --format="html,docx,pdf" --keep-citations=true --preserve-code-blocks=true --output="示例文章与阅读资料/第一轮校对稿"
```

## 把来源留在读者能找到的地方

你可以在文中保留[项目链接](https://github.com/water0523/waterzhijian)，也可以写成上标引用。<sup>[[1]](https://github.com/water0523/waterzhijian)</sup> 切换链接呈现方式时，标号和正文应当仍然容易阅读。

| 交付方式 | 适合什么情况 | 发出之前再检查 |
| --- | --- | --- |
| HTML | 希望保留主题与离线阅读 | 本地图片与公式是否完整 |
| Word | 需要对方继续修改正文 | 标准文档结构与链接 |
| PDF | 希望按页面阅读与打印 | 打印预览、分页与背景 |
| Markdown | 希望继续维护源文章 | 图片引用与备份是否齐全 |

## 最后做一次真正的交付

1. 暂时离开编辑视角，从头读一遍预览。
2. 复制排版，检查标题、代码和引用。
3. 导出一份目标格式，实际打开后再发送。

> 不要让文件名比内容更早过时。标题有变化时，也记得检查这次导出的文件名。

**交付检查：**文章里的外链是示例项目入口，不表示浏览器会自动访问它；离线阅读与联网访问应当能分得清。
